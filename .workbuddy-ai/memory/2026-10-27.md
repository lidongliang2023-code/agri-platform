## 信息资讯模块（agri-info）子系统落地

用户要求：按两个原型（`信息资讯模块_用户端原型_v1.html` / `_运营端原型_v1.html`）开发信息资讯子系统，
样式与既有模块统一、登录走平台统一登录（SSO）、**不得改名或替换已存在的 agri-service**。

### 架构决策
- 新建独立子系统 `agri-info`（后端 8096、库 `agri_info`、表前缀 `info_`），与 `agri-service`（8094）并列，
  不复用其模块名/端口/产物目录。
- 前端两份产物：`agri-info/frontend`（base `/info/`，dev 5197，client_id `info`，权限 `info:consumer`）、
  `agri-info/ops`（base `/info-ops/`，dev 5198，client_id `info-ops`，权限 `info:admin`）。
- SSO 复用 agri-service 已验证的 `sso.tsx`（授权码 + PKCE），只替换会话键前缀与文案，避免协议分叉。
- 私域数据（我的发布/预警/订阅/收藏/问答记录）以 `X-Agri-User` 头区分归属；中文昵称前端
  `encodeURIComponent`，后端 `URLDecoder` 还原（浏览器对非 ASCII 请求头支持不一致）。

### 关键坑
- **`InfoOpsRepository extends InfoRepository` 导致容器里有两个 InfoRepository 候选**，
  `InfoController` 必须 `@Qualifier("infoRepository")`，否则启动即失败。
- 工具环境注入 `SERVER__PORT=54388` 会覆盖 `server.port`，本地起服务需显式 `--server.port=8096`。
- **改了后端源码必须重启**：曾出现「`X-Agri-User` 未解码」的假象，实为运行的是旧 `target/classes`。
- AI 问答检索：整句 `LIKE` 在中文场景几乎必然落空，改为字符二元组重叠度打分 + 作物命中加权。
- 前端依赖：本机 pnpm 在该目录**创建不了 junction**（只生成空的 `@scope` 目录），
  `pnpm install` 报成功但 node_modules 实际为空。改用 `npm install --no-package-lock` 可正常安装；
  锁文件 `pnpm-lock.yaml` 已包含 `agri-info/frontend`、`agri-info/ops` 两个 importer。

### 平台接入改动
- 根 `pom.xml`：`<module>agri-info</module>`（在 agri-service 之后）。
- `pnpm-workspace.yaml`：新增 `agri-info/frontend`、`agri-info/ops`。
- `ops/modules/catalog.json`：`information` 模块改为 info-web(8104 `/info/`) + info-ops(8113 `/info-ops/`) + info-api(8096)。
- `ops/gateway/conf/conf.d/10-upstreams.conf`：新增 `info_backend` → 127.0.0.1:8096。
- `ops/gateway/conf/conf.d/41-info-service.conf`：8104 增加 `/api/v1/info/` 反代（**必须排在 `/api/v1/` 兜底之前**）；
  新增 8113 运营端 server 块。
- `ops/gateway/scripts/publish.mjs`：`info` 改指 `agri-info/frontend`，新增 `info-ops`。
- `ops/local/start-production-stack.ps1`：新增第 11 步 agri-info(8096)，原 11~13 顺延为 12~14，nginx 端口清单补 8113。
- core-platform：`SsoProperties` 与 `application-dev.yml` 登记 `info` / `info-ops` 客户端白名单；
  新增 `V42__info_unified_access.sql` 给 FARMER 加 `info:consumer`、MARKET_OPS 加 `info:admin`。

### 验证结果
- `mvn -pl agri-info -am package` 通过，产出 `agri-info-1.0.0.jar`。
- 用户端 32 个 GET + 运营端 15 个 GET 全部 200；发布供需 / AI 问答 / 内容审核 / 新建预警写链路均成功。
- `tsc --noEmit` 与 `vite build` 两端均通过，产物资源前缀分别为 `/info/`、`/info-ops/`。

## 信息资讯移动端 `agri-info/mobile`（uni-app 三端）

### 工程形态
- 技术栈与 `agri-service/mobile` 完全对齐：uni-app `3.0.0-4010520240507001` + Vue 3.4 + `vite-plugin-uni` + sass + vue-tsc。
- 一套源码三产物：`dist/build/h5`、`dist/build/mp-weixin`、`dist/build/app`（均已构建通过）。
- 35 个页面 + 4 个 tab（资讯 / 行情 / AI问答 / 我的），覆盖移动端原型 37 个 `page-*` 中的全部业务页面
  （发布供应/发布需求合并为 `sd/publish?type=`；专家主页/申请/查询/我的认证独立成页）。
- 无图表库依赖：`components/TrendChart.vue` 用 flex 柱形画趋势，三端渲染一致；涨红跌绿按国内农产品惯例。

### 统一登录（关键设计）
- PC 端走「授权码 + PKCE 整页跳转」，移动端无法整页跳转，改用平台同源
  `/api/v1/sso/login-standalone` 直连换令牌 + `/api/v1/platform/permissions/mine` 校验角色，
  账号体系/令牌/权限词表（`info:consumer`、`info:admin`）与 PC 完全一致。
- 私域数据仍靠 `X-Agri-User`（前端 `encodeURIComponent`，后端 `URLDecoder`）隔离，与 PC 同一约定。
- H5 走同源（dev 代理 → 8096 / 8093）；小程序与 App 用 `VITE_INFO_API_BASE` / `VITE_INFO_AUTH_BASE`
  注入 HTTPS 域名，**可独立上架、独立发版**。

### 平台接入改动
- `pnpm-workspace.yaml`：新增 `agri-info/mobile`。
- `ops/modules/catalog.json`：新增 `info-mobile`（kind `mobile-frontend`，端口 **8114**，`targets: ["h5","mp-weixin","app"]`）。
  8107 已被 service-ops 占用，故取 8114。
- `ops/gateway/conf/conf.d/41-info-service.conf`：新增 8114 server 块（`/api/v1/info/` 必须排在 `/api/v1/` 兜底之前）。
- `ops/gateway/scripts/publish.mjs`：新增 `info-mobile`（`builder: 'uni-app'`，`distDir: dist/build/h5`）。
- `ops/local/start-production-stack.ps1`：nginx 端口清单与访问地址汇总补 8114。
- core-platform：`SsoProperties` 与 `application-dev.yml` 的 `info` client 白名单补
  `:8114`、`:5199`（移动端 H5 与 dev 端口）。

### 坑
- `vue-tsc` 对 `uni.request` 的 `success` 回调参数做结构化校验会报 TS2769，
  必须写成 `success(response) { const body = response.data as Envelope<T> }`，不能显式标注 `{statusCode,data}`。
- 模板里不能直接用全局 `uni.xxx`（编译成 `_ctx.uni` 为 undefined），必须包成 setup 方法再绑事件。

### 验证结果

### 缺陷修复：移动端登录输入框「看得到、点不进、输不了字」
- 现象：H5 / 小程序登录页账号、密码框可见，但点击无光标、无法键入。
- 根因：uni-app 的 `input` 组件自带 `height:1.4em; min-height:1.4em; overflow:hidden` 且 `box-sizing:border-box`
  （产物 `uni.309b647f.css` 中 `uni-input{...}`），而 `.input` 又叠加了 `padding: 20rpx 22rpx`；
  上下各 10px 内边距把 1.4em（22.4px）的内容区压到约 2.4px，内层 `.uni-input-input{height:100%}` 随之塌陷。
- 修复（`src/App.vue` 全局样式）：`.input` / `.select` → `height:82rpx; min-height:82rpx; padding:0 22rpx; line-height:normal`；
  `.textarea` → `height:200rpx; min-height:150rpx; padding:16rpx 22rpx; line-height:1.6`。
  **原则：uni-app 的 input/textarea 只用水平内边距，高度靠显式 height 给，不要用垂直 padding 撑高。**
- 同步给 5 个裸搜索框补 `height:100%`：`news/index`、`market/index`、`sd/index`、`search/index`、`help/index`。
- `pages/login/index.vue`：`<input password>` 裸属性改为 `:password="true"`（小程序产物才是 `password="{{true}}"`，裸属性会变成空串导致密码不掩码）。
- 验证方式：Edge `--headless=new` + CDP（Node 全局 `fetch`/`WebSocket`，无需装 Playwright）实测——
  登录页 `uni-input` 高 42.6px、内层 `input` 40.6px，`focus()` 后 `Input.insertText` 成功写入
  `wangjianguo` / 密码 8 位且 `type=password`；另在 8 个含输入框的页面巡检，`h<20px` 的输入框数量为 0。
- 三端构建与 `vue-tsc --noEmit` 全部通过。
- 已用 `publish.mjs --app info-mobile --version 20261027-info-mobile-r2 --build` 重新发布，8114 指针切到 r2。
  **改完 `agri-info/mobile` 一定要重新 publish，否则 8114 跑的还是 bucket 里的旧产物**（`bucket/info-mobile/versions/<v>/`）。
- 线上 8114 实测：输入框 42.6px、键入正常，点「登录」发出 `POST /api/v1/sso/login-standalone`，
  错误凭据返回「用户名或密码错误」，错误条正常渲染 —— 输入→提交→回显整条链路通。
