### 起点诊断
`userportal/Workbench.vue` 是**纯只读看板**：数据只来自统一认证的主体/实名/资质/消息，

announcements/operation-logs），只是工作台没用。
→ 实测这些接口全部可用（带 Bearer + `X-Agri-Merchant`），数据真实（组织 5/成员 5/商品 3/客户 3）。

### 后端新增（UserWorkspaceController，全部按主体隔离）
- `GET /api/user/customers`（分页+关键词）、`POST`、`PUT /{id}`、`DELETE /{id}`
- `PUT /api/user/orgs/{id}`（只改联系人/电话/地址/简介，认证类字段不让改）
- 服务端强制三件事：`tenant_id` 取当前主体、`customer_code` 自动生成 `CUS{主体}-{序号}`
  （序号取已有最大值+1，不用 count+1，避免删过记录后撞号）、`del_flag/status` 默认值
- 归属不符统一回"客户不存在或不属于当前主体"（两种措辞可被用来探测存在性）

### 前端重构
- 统计卡改 `tenant-summary`；客户档案表格带搜索/分页/新增/编辑/删除；

### 两个真 bug（都是"只有直连数据库/直接请求接口才看得见"）
1. **逻辑删除静默失败**：`setDelFlag(1) + updateById` 不生效 —— 全局配置了
   `logic-delete-field: delFlag`，该字段由 MyBatis-Plus 接管、`updateById` 会跳过它。
   接口返回 200、记录还在。改用 `deleteById`。
2. **客户详情跨主体越权**：`CustomerServiceImpl.getById` 直接 `selectCustomerById(id)`，
   没有归属校验。实测主体 2001 的账号读到了 T1001 的「华联超市连锁」。
   列表接口有过滤、详情接口没做 —— 这类越权最常见的形态。已补 tenant 校验。

## 主数据企业端：组织与权限五页重构 + 重叠检查

### 核心结论：能力归属
| 能力 | 权威源 |
|---|---|
| 账号 / 成员归属 | **core-platform**（platform_user + platform_user_merchant） |
| 加入申请 / 邀请审批 | **core-platform**（platform_merchant_join_request） |
| 组织 / 部门 / 岗位 | **agri-masterdata** |
| 业务角色 | **agri-masterdata**（与平台角色分离） |

### 查出的重叠（已处理）
1. **两套成员数据**：本地 `agri_md_user` 主体 2001 有 5 条（seed_ 种子），
   core `platform_user_merchant` 只有 2 条真实绑定。原成员页读本地表 = 把种子数据当成员。
   → 成员页改读 core 成员接口，本地表只补部门/岗位，匹配不上显示"未分配"。
2. **邀请没有落库实现**：mdm 无邀请表；core 有完整"申请→审批→建绑定"闭环，
   只缺"负责人看待审批列表"。→ **在 core 补接口**，邀请页改审批页，**不建邀请表**。

### 查出的冲突（已修）
1. `department.dept_id` 是 varchar 业务码、真正主键是自增 `id`；`position.dept_id` 是 bigint 指向 `department.id`。
   实体 `@TableId` 指向 dept_id → `selectById` 永远查不到部门。企业端改按 `id` 查。
2. `agri_md_position` 新旧双列：`pos_code/pos_name` NOT NULL 但实体没映射 →
   `Field 'pos_code' doesn't have a default value`。实体补旧列映射，写入时两套同值。
3. **JS 大整数精度**：`parentId` 用 Long 接收，前端传数字会被截断（...101 → ...100），
   改为 String 接收再 parse。

### 新增接口
- core：`GET /businesses/{id}/members`、`GET /businesses/{id}/join-requests?status=pending`
- mdm：`POST/PUT /api/user/orgs|depts|positions|roles`
- 编码/层级/路径全服务端生成；tenant 强制；归属不符统一拒绝

## 运维：后台服务会自动退出，需定期复检

本机后台 java 进程（`run_in_background` 启动的 jar）**跑数小时后会自己退出**，
本轮遇到 mdm(8083) 与 core-platform(8093) 各退出一次。表现是网关返回 502、页面打不开。

复检顺序（照抄即可）：
1. `Get-NetTCPConnection -LocalPort 3306,6379,8083,8093 -State Listen` —— 确认 MySQL/Redis/后端
2. 缺谁补谁：
   - core：`cd core-platform && MYSQL_PASSWORD=root java -jar core-app/target/core-app-1.0.0.jar --server.port=8093`
   - mdm：`cd agri-master-data/backend && java -jar target/agri-master-data-1.0.0.jar --server.port=8083 --spring.datasource.password=root`
3. `node scripts/health-check-subsystems.mjs` → 应为 14/14

⚠️ **重启前先确认端口没有活进程**：`curl` 到 8083 返回 502 是沙箱代理层伪造的，
不代表后端没起来（真正没起来时 `Get-NetTCPConnection` 也查不到监听）。
重复启动会报 `Port 8083 was already in use` 然后退出 —— 无害，但别误判成"启动失败"。

## 成员任职档案：打通"账号 → 组织位置"（组织与权限真正闭环）

### 上一轮的错误归因（已纠正）
上一轮说"部门/岗位未分配是因为种子数据对不上"——**错了**。真实原因：
`agri_md_user` 根本没有 `dept_id` / `position_id` / `platform_user_id` 三列（只有 `org_id`），
`/api/user/members` 也不返回 `deptName` / `positionName`。前端读 `local?.deptName` 永远是 undefined，
**无论数据怎么对都显示不出来**。

### 为什么不给 agri_md_user 加列
1. `password` 是 NOT NULL —— 给 SSO 账号建本地档案就得填假密码，把"认证凭证"和"员工档案"混一起；
2. `username` 是**全局唯一** —— 同一账号可在多个主体任职，一条本地档案装不下；
3. 表里已有 5 条种子数据 —— 加列会让它们看起来像真员工。

### 新表 agri_md_member_profile（只存"账号 ID → 组织位置"）
```
tenant_id / platform_user_id / org_id / dept_id / position_id / job_status
UNIQUE (tenant_id, platform_user_id)
```
- **不冗余用户名手机号**：账号信息以 core 为准，改名后这里不会过期
- 三个位置字段统一 **VARCHAR**：三表主键类型不同（organization.id 雪花 Long、
  department.id 自增 BIGINT、position.position_id 雪花 VARCHAR），存字符串免去来回转换
- schema.sql 是 `mode: always` + `CREATE TABLE IF NOT EXISTS`，**加列不会自动生效**，
  必须同时对现有库执行建表/ALTER（这次是新建表所以直接 CREATE）

### 接口（UserWorkspaceController）
- `GET /api/user/member-profiles`（含 orgName/deptName/positionName 回查）
- `PUT /api/user/member-profiles/{platformUserId}`（upsert）
- `DELETE /api/user/member-profiles/{platformUserId}`

### 信任边界（关键设计）
mdm 看不到认证库 `platform_user_merchant`，**无法校验 platformUserId 是否真属于本主体**。三层兜：
① 按 tenant 隔离；② 组织/部门/岗位必须属于本主体；③ 展示时**以 core 成员列表为主表左连接**，
孤儿记录显示不出来。所以伪造 ID 最多留一条看不见的空记录。

### 两个防呆校验
- **三项全空拒绝**：否则前端漏传字段就静默抹掉任职信息，接口还返回 200。清空走 DELETE。
- **岗位必须属于所选部门**：否则出现"在质检部任职、岗位属于仓储部"的自相矛盾档案。

### 前端
成员页重写：三级联动（组织→部门→岗位），选部门自动补组织，换组织清空部门，
行内「分配/调整」+「清除」，副标题显示"共 N 人 · 已分配职务 M 人"。
以成员列表为主表 join 任职档案，**孤儿记录不显示**。
