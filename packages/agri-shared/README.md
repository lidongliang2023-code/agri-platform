# @agri/shared · 跨子系统共享资产

> 依据：《农业产业互联网平台技术架构文档 V2.0》第 4.8 节「共享资产生命周期与前端团队协作规范」
> 定位：路线 2「先基建再拆」的**第 1 项**（共 4 项：共享资产 / CLI 模板 / 统一 SSO / 域名与网关规划）

## 为什么要有这个包

V2.0 第 2.3 节的 D1 决策要求九大子系统做成独立应用（独立仓库/域名/部署/登录页）。
独立之后如果每个子系统各自复制一套组件、主题、工具，就退化成九套烟囱——
V2.0 4.8 节明确要求用「共享组件库 + CLI 模板 + SSO」抵消这种重复。本包就是那个共享组件库的家。

## 现状与已知前提

| 项 | 状态 |
| :-- | :-- |
| 工作区（`pnpm-workspace.yaml`） | 已建，**只含新包**；现有前端刻意未纳入（见该文件注释） |
| 本包内容 | 空壳（仅出口 `src/index.ts`） |
| 待迁资产规模（实测） | `types` 18 文件/3,358 行、`utils` 4/1,880、`components` 5/421、`layouts` 4/278、`styles` 2/126 —— 共 33 文件、约 6,000 行 |
| 工具链 | pnpm 11.25.0（文档要求 8.x，同族；要严格对齐用 corepack 固定） |

## 搬迁批次（**每批独立提交、独立验证，不做大爆炸式搬迁**）

顺序按"风险从低到高"，不是按目录字母：

| 批次 | 内容 | 为什么这个顺序 | 改动面预估 |
| :-- | :-- | :-- | :-- |
| B1 | `styles/`（2 文件 126 行，如 `theme.ts`、`global.less`） | 无业务依赖、被引用点少 | 小 |
| B2 | `types/`（18 文件 3,358 行） | **纯类型，编译期资产，无运行时行为**，迁移不会改变运行结果 | 中（引用多但机械） |
| B3 | `utils/`（4 文件 1,880 行） | 工具函数，可补单测后迁；V2.0 4.3 要求 Vitest | 中 |
| B4 | `components/`（5 文件 421 行） | 跨子系统复用价值最高，但依赖前面几批 | 中 |
| B5 | `layouts/`（4 文件 278 行） | 与路由、登录页、子系统入口强耦合，**拆分前端时才动它** | 大 |

## 每批的验证协议（缺一项不算完成）

1. `node node_modules/typescript/bin/tsc --noEmit` → 必须 `EXIT=0`（**不要用 `npx tsc`，那是假绿**）
2. `node node_modules/vite/bin/vite build` → 必须成功
3. 浏览器打开 2~3 个**代表页**（至少含用户端 1 页 + 运营端 1 页）确认无回归，附页面实测输出
4. 该批单独提交，提交信息写明批次号与验证结论

## 什么**不该**进这个包

- 子系统专有业务逻辑（例如食品安全的 5 个页面、报表口径）——那是子系统的资产，进包会重新变成耦合；
- 与后端契约强绑定的 API 封装（`api/*`）：V2.0 要求各子系统独立部署、独立发布，接口层应随子系统走，
  只有**确有多系统共用**的接口封装（如 SSO 用户信息）才考虑上提；
- 任何**未验证能用**的东西：这个包是九个子系统的共同底座，一个坏资产会同时污染九个系统。
