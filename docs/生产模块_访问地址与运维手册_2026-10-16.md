# 生产管理模块 · 访问地址与运维手册（2026-10-16）

> 本手册只写这一台机器上"现在真实可用"的地址与命令，都经过实测；公网域名/TLS 不在本机部署范围内（见文末"还不是生产地址"一节）。

## 一、访问地址

| 用途 | 地址 | 备注 |
|---|---|---|
| **用户端入口** | `http://localhost/production/login` | 生产管理模块主入口（农场/地块/计划/任务/农资/采收/质量/追溯/生长/IoT/报表等） |
| **运营端入口** | `http://localhost:8190/` | 监管侧入口（农场监管、质量监管、食品安全、统计报表、审批、知识库/SOP…） |
| 网关同域 API | `http://localhost/api/v1/production/**` | 前端同域调用；响应头 `X-Served-By` 标明本次由谁服务（`agri-production` / `core-platform` / `core-platform-fallback`） |
| 登录（取访问令牌） | `POST http://localhost/api/v1/auth/login` | body：`{"username":"admin","password":"Admin@123","marketId":1}`，令牌在 `data.accessToken` |

**登录账号**：`admin` / `Admin@123`（演示环境，`marketId=1`）。

## 三、前端版本与发布

- 发布形态：`ops/gateway/bucket/prod/` 下"**版本目录 + 指针**"——`prod/index.html` 与 `prod/manifest.json` 指向 `prod/versions/<版本>/`。
- 当前线上版本记录在 `ops/gateway/bucket/prod/manifest.json` 的 `version` 字段（本文当日为 `20261016-v2`）。
- **发布用脚本，不要手敲**：
  ```bash
  node ops/deploy-prod-frontend.mjs --version=20261016-v3   # 构建(带 base) + 发布 + 发布后巡检
  node ops/deploy-prod-frontend.mjs --dry-run               # 只算版本号、打印步骤
  ```
  脚本内置两道防线：构建产物若不含 `/prod/versions/<版本>/` 前缀即中止（漏带 `base` 会让产物按根路径拼 chunk，表现为"页面能开、一堆 MIME 报错"）；发布后巡检白屏/未捕获异常/console 错误超基线则自动回滚指针。
- 手工回滚：把 `prod/versions/<上一版本>/index.html` 覆盖到 `prod/index.html`，并把 `manifest.json` 的 `version` 改回上一版本。

## 五、已知基线（看数字前先知道这些）

- 用户端全量巡检允许**最多 1 个页面**有 console 错误：病虫害识别页的 `demo.example.com` 图片域名不可解析（种子数据问题，与本模块代码无关）。
- 探针脚本报出的"缺口"只统计到**本服务没有处理器**的路径；平台域路径（`/admin/tenants`、`/alerts/rules`、`/settings/tenant`、`/roles`）按口径不计入。
- 探测/写操作跑完要复位演示基线：`update_time = create_time`，以及探针会打 `POST /iot/devices/1/heartbeat`（设备心跳/状态要一起复原）。

## 六、还不是"生产地址"

上面全是**本机地址**。网关配置为这个模块预留的正式域名是 `prod.agri-platform.com`（本地另挂了 `prod.agri.local`）。要变成公网可访问，还需要：域名解析/hosts、TLS 证书、把 nginx 与后端部署到目标服务器 —— 这些不在当前这台机器的部署范围内，需要目标环境信息后才能做。
