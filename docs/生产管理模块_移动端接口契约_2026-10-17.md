# 生产管理模块 · 移动端接口契约（2026-10-17）

> 依据：《生产管理模块移动端 PRD V1.1》第 6 章（API 设计）、第 10 章（食品安全四层防线）、第 11 章（AI 能力）。
> 本文件是**移动端与后端之间的接口约定**：哪些已实现、返回什么、哪些是 501 占位、以及我们与 PRD 的路径偏差。
> 实现代码：`agri-production/backend/.../controller/FoodSafetyController.java`、`AiNotAvailableController.java`。

## 0. 一句话结论

PRD 6.3 的移动端专有接口里，**能落地的两条食品安全校验已经真实现**（休药期、投入品四重校验），
**AI 类 13 条按 501 占位并写明原因**（前端可以按契约接上、接上后用户看到的是后端原文而不是假结果），
**移动端基础设施 3 条（推送注册 / 离线同步 / 定位上报）仍待产品定策略，暂不占位**。

## 1. 路径偏差（需要产品确认的一件事）

| | PRD 6.3 写法 | 本部署实现 |
| --- | --- | --- |
| 食品安全校验 | `/api/v1/mobile/production/food-safety/*` | `/api/v1/production/food-safety/*` |
| AI 能力 | `/api/v1/mobile/production/ai/*` | `/api/v1/production/ai/*` |

**理由**：网关是**按业务域分段**路由的（`ops/gateway/conf/conf.d/20-prod.conf` 里维护段名白名单，
未列入的段会回退到平台侧）。为"客户端是手机还是电脑"再开一套 `/api/v1/mobile/**` 前缀，
会让同一份业务出现两条入口、两处要维护的鉴权与租户校验；而这两条校验规则 PC 端的
`/production/food-safety/*` 页面同样适用，放同一域名下 PC 可以**直接复用同一契约**。

**若产品要求严格对齐 PRD 路径**：在网关加一条别名 location（`/api/v1/mobile/` → `agri_production`）
即可，服务端代码不用改；届时同步改移动端 `api/production.ts` 里的 url 常量（集中在一处）。

## 2. 已实现：采收前休药期校验（PRD §4.4.2 Step3 / §10.3）

```
GET /api/v1/production/food-safety/pre-harvest-check
    ?plotId=1                         # 单地块（新建采收页）
    &plotIds=1,2                      # 或多地块（PRD §10.3 的多地块对比页），二者取其一
    &plannedHarvestDate=2026-10-17    # 计划采收日期，缺省按今天
```

响应（单地块时把 `plots[0]` 的字段摊平到根上，页面少解一层）：

```json
{
  "plannedHarvestDate": "2026-10-17",
  "checkResult": "pass | block",
  "dataComplete": true,
  "earliestHarvestDate": "2026-11-07",
  "daysRemaining": 21,
  "lastApplication": {
    "usageId": 102, "inputId": 102, "productName": "稻瘟灵乳油",
    "applicationDate": "2026-10-17", "preHarvestIntervalDays": 21,
    "earliestHarvestDate": "2026-11-07", "operatorId": 1
  },
  "aiAdjusted": false,
  "basis": "按地块最近一次带安全间隔期的用药记录 + 该投入品的安全间隔期推算；…",
  "plots": [ /* 多地块时每块一条，并给整组 checkResult 与 blockedPlots */ ]
}
```

**判定规则（服务端唯一一份，PC 与移动端共用）**：

1. 取该地块**最近一条带安全间隔期的用药记录**：优先记录自身的 `safety_interval_days`，
   缺失时回退到投入品档案 `agri_prod_input_material.safety_interval`（历史记录常缺前者的列）；
2. `earliestHarvestDate = applicationDate + interval`；计划采收日早于它 → `block`，否则 `pass`；
3. **该地块没有任何带间隔期的用药记录** → `pass` + `dataComplete=false` + 说明
   （休药期不构成约束，而不是"校验通过"）；
4. `aiAdjusted` **恒为 false** —— 本部署没有 AI 模型，不做"高温降解加速"之类的自适应缩短。

## 3. 已实现：投入品四重校验（PRD §10.2）

```
POST /api/v1/production/food-safety/compliance-check
{ "inputId": "102", "plotId": "1", "dosage": 2, "unit": "瓶", "usageDate": "2026-10-17" }
```

响应（每项 `result` + `detail`，前端必须把 `UNKNOWN` 显式画出来）：

| 项 | 结果范围 | 数据来源 / 为什么是这个结果 |
| --- | --- | --- |
| `stock` 库存 | `PASS` / `WARNING` / `UNKNOWN` | 投入品档案 `stock_qty` 与本次用量比较；缺用量或库存则 `UNKNOWN` |
| `timing` 用药时机 / 休药期 | `PASS` / `WARNING` / `UNKNOWN` | 档案 `safety_interval`：有间隔期则给出"本次使用后最早可采收日"；农药没登记间隔期 → `WARNING`；非农药类 → `UNKNOWN`（本项不适用） |
| `compliance` 禁用清单 | 目前恒 `UNKNOWN` | **本部署没有投入品级禁用/限用清单主数据**（库里只有标准编号清单与检测结果），如实标未校验 |
| `interaction` 复配交互 | 目前恒 `UNKNOWN` | 没有农药复配/交互规则表 |
| `cost` 成本替代 | 目前恒 `UNKNOWN` | 投入品档案没有价格列，无法比较替代方案 |

`overall` 口径（**关键**）：`BLOCK` &gt; `WARNING` &gt; `UNKNOWN` &gt; `PASS`。
也就是说只要还有一项没校验，整体就**不会**是 `PASS` —— 不把"没校验"算成"通过"。
`alternativeRecommendations` 恒为空数组（没有依据就不编替代品）。

前端行为约定：`overall=BLOCK` 时**不提交**；`WARNING/UNKNOWN` 时弹一次确认（列出未校验项）后允许继续；
校验接口不可用时按安全红线 fail-closed，不静默放行。

## 4. AI 能力：501 占位 + 原因 + 可用替代（PRD §11 / §10.4）

全部返回 `{"code":501,"message":"<能力>未接入。本部署未接入任何识别/预测模型，按口径不提供该结果（不做近似、不用样本量推算）。可用的替代：…"}`

| 端点 | 对应 PRD | 替代方案（写在 message 里） |
| --- | --- | --- |
| `POST /ai/pest-detection`、`POST /ai/pest-detect` | §4.6.1 / §11 | 历史诊断记录 `GET /ai` |
| `POST /ai/assistant/chat` | §11.2 AI 农艺师 | 知识库 `/admin/knowledge`、农事记录 `/tasks` |
| `GET /ai/prescription/list`、`GET /ai/prescription/{id}`、`POST /ai/prescription/{id}/confirm`、`GET /ai/prescription/{id}/tracking` | §11.3 AI 种植处方 | 任务执行记录 `/tasks/{id}/records` |
| `GET /ai/alert/list`、`GET /ai/alert/{id}`、`POST /ai/alert/{id}/execute` | §11.5 AI 预警中心 | 已入库告警 `/alerts`、生长监测 `/growth` |
| `POST /ai/verify` | §10.4 消费者 AI 验真 | 溯源码真实链路 `GET /trace/full-chain/trace/{code}`、检测记录 `/quality` |
| `GET /ai/remote-sensing/plot/{plotId}` | §11.4 遥感 | 地块台账 `/plots/{id}`、土壤记录 `/plots/{id}/soil/latest` |
| `GET/POST /ai/yield-forecast`、`GET /ai/yield-forecast/plot/{plotId}`、`GET /ai/yield-forecast/accuracy` | §11 产量预测 | 采收台账 `/harvests` 与地块面积 |

**为什么占位而不是 404**：这是本仓已有的定论（见 `AiNotAvailableController` 类注释）——
404 会被网关回退到平台侧的骨架实现，而平台侧对某些预测接口返回的是"样本量 × 100"这种
**编出来的数字**。501 + 原因把"没有模型"做成看得见的回答，前端也能按契约把页面接上。

## 5. 移动端基础设施 3 条：**策略已定、按 501 占位**（2026-10-17 拍板）

这三条在上一版是"未占位、等产品定策略"；现已按建议定下口径，**接口按契约占位**，
实现仍缺（缺的是渠道/表结构，不是口径），所以返回 501 + 已定口径 + 现成替代：

| 端点 | PRD | **已定口径** | 当前返回 |
| --- | --- | --- | --- |
| `POST /api/v1/production/mobile/push/register` | §5.3 推送 | 小程序走**微信订阅消息**（用户主动订阅的模板消息），PC/App 走站内消息；**不接厂商推送通道** | 501：本部署没有模板 ID 与订阅授权，注册了也发不出消息，故不落库；替代 = 站内消息 `GET /messages` |
| `POST /api/v1/production/mobile/sync` | §5.2 离线 | **只读缓存 + 三类写操作离线队列**（任务过程记录 / 投入品使用 / 采收登记），冲突以服务端为准、客户端队列幂等重放；不追求任意表单离线写 | 501：服务端还没有幂等键与冲突合并实现，此时接收队列会静默丢数据，故不接收 |
| `POST /api/v1/production/mobile/location/report` | §5.5 定位 | 只采集**打卡点**（地块中心 + 当前坐标 + 时间），**不采连续轨迹**，上报前需显式授权 | 501：还没有对应落库表与授权流程，不接收坐标（位置属敏感数据） |

为什么定了策略仍不"假装实现"：这三条一旦"接口能调通但什么都没发生"，离线就会丢数据、
推送就永远收不到、定位就静默不落库 —— 比明确 501 更糟。**要实现时照着上表的路径与口径做即可。**
