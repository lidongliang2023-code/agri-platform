# 生产管理模块 · 移动端（小程序）实现说明

> 依据：《生产管理模块移动端 PRD V1.1》（2026-09）第 3 章信息架构、第 4 章页面设计、第 6 章 API 设计、第 9 章实施计划。
> 工程：`agri-production/miniprogram`（uni-app 3 + Vue3 + TS + Vite，一套源码产出 **微信小程序 + H5**，后续可加 App）。
> 本文件记录"做了什么、对应 PRD 哪一节、哪些没做/为什么、怎么构建与验证"。

## 1. 为什么选 uni-app（对齐 PRD 9.3 与仓库现状）

PRD 9.3 给了三条路线（RN+小程序 / Flutter / 小程序优先）。本仓已有一个 uni-app 形态的小程序
（`agri-iot/miniprogram`，同为 uni-app 3.0.0-4010520240507001 + Vue3 + TS），因此移动端沿用同一技术栈：

- **端覆盖**：一套代码 → 微信小程序（PRD 9.2 交付物之一）+ H5（便于联调与验收）+ 可继续出 App；
- **与 PC 端复用**：请求契约（`/api/v1`、Bearer、业务码 `code === 0`）、状态字典（任务状态/优先级/入库状态）
  与 PC 端 `agri-shared` 同值域，同一任务在两端不会显示成两个状态；
- **不新增后端**：PRD 6.1 的口径就是"复用 PC 端用户端 API，路径保持一致"。

## 2. 目录与工程结构

```
agri-production/miniprogram/
├── package.json / tsconfig.json / vite.config.ts / index.html
└── src/
    ├── main.ts / App.vue（全局样式：卡片/标签/按钮/表单行等原子类）
    ├── manifest.json / pages.json（20 个页面 + 5 个底部 Tab）
    ├── utils/request.ts   请求层（H5 同源 / 小程序绝对地址；code===0 判成功；401 回登录）
    ├── utils/auth.ts      登录态 + 当前农场上下文；utils/auth-helper.ts 统一出口
    ├── utils/format.ts    状态字典与格式化（与 PC 端同值域）
    ├── api/production.ts  生产域接口封装（farms/plots/tasks/inputs/harvests/trace/alerts/messages/ai）
    └── pages/…            20 个页面（见下表）
```

底部 Tab 与 PRD 3.1 完全一致：**工作台 / 农场 / 农事 / 采收 / 我的**。

## 4. 接口对照（PRD 6.1 复用清单）

| 功能 | 复用端点 | 备注 |
| --- | --- | --- |
| 农场 | `GET /farms/all`、`GET /farms/{id}` | 登录后立刻建"当前农场"上下文 |
| 地块 | `GET /plots`、`GET /plots/{id}`、`GET /plots/{id}/soil/latest` | 土壤无记录时后端 404 → 页面显示「—」，不当作整页失败 |
| 任务 | `GET /tasks`（入参 `page/size`，**不是** pageNum/pageSize）、`GET /tasks/{id}`、`POST /tasks`、`POST /tasks/{id}/start`、`POST /tasks/{id}/submit`、`GET/POST /tasks/{id}/records` | 与 PC 端同一入参口径 |
| 投入品 | `GET /inputs`、`GET /inputs/{id}`、`GET /inputs/{id}/stock-flows`、`GET/POST /inputs/usages` | 使用记录按 `plotId` / `taskId` 过滤 |
| 采收 | `GET /harvests`、`POST /harvests`、`GET /harvests/{id}`、`POST /harvests/{id}/generate`、`POST /harvests/inventory/in`、`GET /harvests/inventory` | 入库契约是 `batchId` + **`quantity`**（不是 qty） |
| 溯源 | `POST /trace/scan?code=`、`GET /trace/full-chain/trace/{code}` | 扫码会落一条扫码记录（真实写操作） |
| 告警/消息 | `GET /alerts`、`GET /alerts/{id}`、`GET /messages`、`GET /messages/unread-count`、`PATCH /messages/read-all` | — |
| 人员 | `GET /members` | 下拉取值用**数字主键 `id`**，`memberId`（DEMO-MEM-001）会被后端静默丢弃（PC 端踩过） |

## 5. 合规校验的口径（不谎报"通过"）

PRD §4.3.4/§10.2 要求投入品"四重校验"（合规 / 交互 / 时机 / 成本），`POST /api/v1/mobile/production/food-safety/compliance-check`
在**本部署不存在**。移动端因此只做**能用真实数据算出来**的项，其余明确标注"未校验"：

| 校验项 | 数据来源 | 结果口径 |
| --- | --- | --- |
| 库存校验 | 投入品 `stockQty` vs 本次用量 | 通过 / 预警（超库存） |
| 安全间隔期 | 投入品 `safetyInterval` + 使用日期 | 给出"最早可采收日" |
| 休药期冲突 | 该地块近期使用记录 | 冲突 / 未发现冲突 |
| 禁用清单 | — | **未校验**（本部署无清单接口） |
| 用量标准 | — | **未校验**（本部署无标准接口） |

新建采收的 Step3 是同一套算法，并且是**硬拦截**（PRD §4.4.2 要求"不合格则拦截"）：
采收日期早于"最近一次用药日 + 安全间隔期"时不允许提交；缺安全间隔期时显示"无法判定"而不是放行。

## 7. 构建、预览与验证

```bash
cd agri-production/miniprogram
npm install
npm run build:mp-weixin   # 产物 dist/build/mp-weixin（微信开发者工具导入，勾"不校验合法域名"）
npm run dev:h5            # H5 预览：http://localhost:5300（vite 代理 /api → 网关）
npm run build:h5          # H5 产物 dist/build/h5
```

联调脚本（仓库根目录）：

```bash
node scripts/e2e-mobile-mvp.mjs --shot=<截图目录>
```

**实测结果（2026-10-17）**：40 条断言全绿、失败 0 项。

- 登录：账号密码 → 统一认证中心拿令牌（H5 端输入必须走"原生 setter + input 事件"，
  逐字符 `type()` 会被 uni-app 受控组件吃掉，只剩首字符 —— 这个坑已写进脚本注释）；
- 5 个 Tab + 地块详情/任务详情/新建任务/新建采收/投入品/库存/溯源/AI/消息/告警/设置共 20 页全部渲染；
- 页面共发出 **33 次生产域接口调用，全部 2xx**，无 4xx/5xx、无未捕获异常、无缺失静态资源；
- 小程序端 `npm run build:mp-weixin` 产出 **20 个页面 + 5 个 Tab** 的 `app.json`，可导入开发者工具。
