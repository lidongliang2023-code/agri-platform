> 依据：《生产管理模块移动端 PRD V1.1》（2026-09）第 3 章信息架构、第 4 章页面设计、第 6 章 API 设计、第 9 章实施计划。

## 1. 为什么选 uni-app（对齐 PRD 9.3 与仓库现状）

PRD 9.3 给了三条路线（RN+小程序 / Flutter / 小程序优先）。本仓已有一个 uni-app 形态的小程序
（`agri-iot/miniprogram`，同为 uni-app 3.0.0-4010520240507001 + Vue3 + TS），因此移动端沿用同一技术栈：

- **端覆盖**：一套代码 → 微信小程序（PRD 9.2 交付物之一）+ H5（便于联调与验收）+ 可继续出 App；
- **与 PC 端复用**：请求契约（`/api/v1`、Bearer、业务码 `code === 0`）、状态字典（任务状态/优先级/入库状态）
  与 PC 端 `agri-shared` 同值域，同一任务在两端不会显示成两个状态；
- **不新增后端**：PRD 6.1 的口径就是"复用 PC 端用户端 API，路径保持一致"。

## 5. 合规校验的口径（不谎报"通过"）

PRD §4.3.4/§10.2 要求投入品"四重校验"（合规 / 交互 / 时机 / 成本），`POST /api/v1/mobile/production/food-safety/compliance-check`
在**本部署不存在**。移动端因此只做**能用真实数据算出来**的项，其余明确标注"未校验"：

| 校验项 | 数据来源 | 结果口径 |
| --- | --- | --- |
| 库存校验 | 投入品 `stockQty` vs 本次用量 | 通过 / 预警（超库存） |
| 安全间隔期 | 投入品 `safetyInterval` + 使用日期 | 给出"最早可采收日" |
| 休药期冲突 | 该地块近期使用记录 | 冲突 / 未发现冲突 |
| 禁用清单 | — | **未校验**（本部署无清单接口） |
| 用量标准 | — | **未校验**（本部署无标准接口） |

新建采收的 Step3 是同一套算法，并且是**硬拦截**（PRD §4.4.2 要求"不合格则拦截"）：
采收日期早于"最近一次用药日 + 安全间隔期"时不允许提交；缺安全间隔期时显示"无法判定"而不是放行。

### 9.2 踩坑记录（都写进脚本注释，供后来人少走）

1. **H5 的 `<picker>` 是滚轮，点选项不改变选中值**：第一版脚本 `click` 了目标选项就点「完成」，
   结果拿到的还是索引 0 的旧值 —— 投入品使用记录因此落到了**错误的地块**上（库里 plot_id=238，
   而页面显示的是另一块地）。现在必须像真人一样**拖动滚轮**，并且每拖一次回头核对
   `.uni-picker-item.selected`，最后按字段文案复核。
2. **滚轮有手势阈值且不循环**：本机实测位移 <90px 完全不生效，100px 约走 4 项、170px 约走 6 项且会冲过 1 项；
   列表到底后继续拖不会绕回。所以用例选的是**滚轮可达**的两块地（索引 0/4/6：E区休耕地、A区-地块2），
   并且**任务类型**也换成可达项（除草，索引 4）；4 项以下的小列表（如优先级）不做滚轮操作，
   改为断言"默认值原样落库"。
3. **长页面要先 `scrollIntoView`**：「投入品录入」页的表单在首屏之外，直接按 `getBoundingClientRect`
   的坐标拖等于拖在空白处（表现为"怎么拖都不动"）。
4. **`mysql.exe` 输出中文会乱码**：加 `--default-character-set=utf8mb4`，并且断言用 ASCII 流水号，
   避免"数据明明对、脚本却说不对"。
5. **清理放在 `finally`**：中途断言失败也要把本轮造的数据软删掉，不留脏数据。

### 10.1 新增两个分组

| 分组 | 默认 | 查什么 | 为什么值得进 CI |
| --- | --- | --- | --- |
| `mobile` | **跑** | ① `pages.json` 的页面清单与 `src/pages/**/*.vue` 是否一一对应；② 底部 Tab 是否都指向已登记页面（且正好 5 个，对齐 PRD 3.1）；③ 源码里引用的每个 `/pages/...` 是否都已登记；④ 接口层是否只打 `/api/v1/production` 或 `/api/v1/auth`；⑤ 是否存在对后端**尚未提供**的 `/api/v1/mobile/**` 的调用；⑥ 有 `dist/build/mp-weixin` 产物时，核对产物页面清单与源码一致 | 这几类问题都是"跑得起来、点下去才炸"或"静默调了个不存在的接口"，静态就能挡住；全部只读文件，CI 无网络无数据库也能跑 |
| `mobile-e2e` | 跳过（`--mobile-e2e` 打开） | 依次执行 `scripts/e2e-mobile-mvp.mjs`（读链路巡检）与 `scripts/e2e-mobile-writes.mjs`（写链路落库），把各自的汇总行记进门禁 | 需要生产栈 + H5 dev server，CI 里没有；本地发布前跑一次即可 |

### 10.2 关于第 ③ 条的取法（踩过的坑）

最初只扫 `navigateTo({ url: '...' })`，结果漏掉了**数据驱动**的跳转（工作台快捷入口是一张
`{ path: '/pages/xxx' }` 表，点击时才 `go(entry.path)`）；改成"扫 `url:` 位置"又会把
`` `${base}?id=1` `` 这种变量拼接误报成非法路径。现在的口径是：
**扫源码里所有 `/pages/...` 字面量**——数据驱动的目标在表里就是字面量，会被扫到；
变量拼接的目标其真实取值一定以字面量出现在调用处（如 `goDetail('/pages/tasks/detail', id)`），
同样会被扫到且不会误报。当前实测覆盖 16 处引用。

### 11.1 动手前先核对写契约，发现两个"选了也白选"的字段

`POST /plots` 的入参是 `PlotSaveDTO`。逐字段核对后发现：

| 字段 | 表列 / 实体 | DTO | 后果 |
| --- | --- | --- | --- |
| `irrigationType` | `irrigation_type` 有、实体有 | **缺** | 页面选了灌溉方式 → 后端**静默丢弃**（PC 端新增地块表单一直在传它） |
| `cropVariety` | `crop_variety` 有、实体有 | **缺** | 品种同样写不进去（而地块详情/列表都在显示这一列） |

这和采收登记的 `operator_id`（传 `DEMO-MEM-001` 被 `toLong` 丢成 null）是同一类问题：
**接口收下了、字段没了、页面还显示着"已保存"**。由于服务层是 `BeanCopyUtils.copy(dto, plot)`，
字段同名即自动映射，所以修复就是在 DTO 里补上这两项（不改 SQL、不改服务）。

实测（`POST /plots` 后直查库）：`irrigation_type=滴灌`、`crop_variety=中杂9号`、`center_longitude=113.610000`
——补之前这三项里前两项恒为空。

### 11.2 移动端页面（`pages/plots/create`）

按 PRD 三步走，每步都有校验（必填没填不许下一步）：

1. **Step1 基础信息**：地块名称（必填）、面积、土壤类型（滚轮）、灌溉方式（滚轮）；
2. **Step2 位置定位**：「获取当前位置」调 `uni.getLocation`，**拿不到就如实提示手填**（H5 常因权限/非 https 失败）；
   经纬度要么都填、要么都留空（只填一个会被拦下）；
3. **Step3 作物信息**：当前作物、作物品种、种植日期、预计采收（选种植日期后给一个"90 天后"的起点，可改）；
4. **成功页**：回查一次详情拿到地块编号（创建接口只返回主键），提供「查看地块详情 / 继续添加」。

地块列表页顶部加了「＋ 新增地块」入口；`pages.json` 同步登记（门禁会校验两者一致）。

### 11.3 联调与清理

`scripts/e2e-mobile-writes.mjs` 增加第 ⑤ 段：走完三步 → `POST /plots` → 按唯一地块名回查主键 →
详情接口与 MySQL 双向核对（名称/面积/土壤类型/**灌溉方式**/**作物品种**/经度）→ `DELETE /plots/{id}` 清理。

**实测（`node scripts/e2e-mobile-writes.mjs`）：全绿、失败 0 项**；四处清理都是软删（`deleted=1`）。
随后 `node ops/ci/verify.mjs --mobile-e2e`：**通过 22 项 / 警告 4 / 跳过 1 / 失败 0**（移动端 21 页、
产物一致、两个端到端脚本都在门禁内跑通）。

### 11.4 顺带发现（PC 侧，本轮未动）

PC 端 `pages/user/plots/Create.tsx` 的提交载荷里有两个 DTO 不接受的字段：
`geoBoundary`（把经度/纬度/坡度/边界打包成一个 GeoJSON）和 `plantingType`；
而它顶部的注释还写着"后端 PlotInfoEntity 无经度 / 纬度 / 边界等独立列"——
实际上 `agri_prod_plot_info` 早有 `center_longitude` / `center_latitude` / `boundary` 列，
DTO 也一直有 `centerLongitude` / `centerLatitude` / `boundary`。

也就是说：**PC 端新增/编辑地块时填的位置信息很可能一直没落库**（写进了后端不认识的键）。
这属于 PC 端与后端契约的历史偏差，改它会影响 PC 页面与已有数据回填逻辑，**没有在本轮擅自改**，
记在这里等排期。移动端这次用的是 DTO 认可的字段，不受影响。

## 12. 食品安全校验服务端化 + AI 契约定稿（2026-10-17 追加，用户选 A 方案）

移动端剩下的缺口都被"后端没有对应端点"挡着。本轮按 A 方案推进：**能落地的两条校验真实现，
AI 能力按 501 占位把契约定死**。接口契约单独成文：
[生产管理模块_移动端接口契约_2026-10-17.md](./生产管理模块_移动端接口契约_2026-10-17.md)。

### 12.1 休药期与投入品校验改为服务端唯一一份

- 新增 `FoodSafetyController` + `IFoodSafetyService` / `FoodSafetyServiceImpl`：
  `GET /food-safety/pre-harvest-check`（单地块/多地块）与 `POST /food-safety/compliance-check`；
- **规则不再各算一套**：以前小程序与 PC 端各自在前端算休药期，现在都取服务端结论；
- **能力边界如实标注**：时机与库存是真数据算的；禁用清单 / 复配交互 / 成本替代三项因为本部署
  **没有相应主数据**（库里只有标准编号清单与检测结果），一律返回 `UNKNOWN` 并写明原因；
  整体结论按 `BLOCK > WARNING > UNKNOWN > PASS`，**不会把"没校验"算成通过**；
- 前端：新建采收页 Step3 与投入品录入页的校验区都改为展示服务端结果，并在页面上写明
  "结论来自服务端校验（规则与 PC 端同一份）"；`BLOCK` 不提交，`UNKNOWN/WARNING` 弹一次确认
  （列出未校验项），**校验接口不可用时 fail-closed**（安全红线不因接口挂了就放行）。

### 12.2 AI 能力：13 条 501 占位（契约冻在代码里）

PRD §11 / §10.4 的 AI 端点（农艺师对话 / 拍照识病 / 种植处方 4 条 / AI 预警 3 条 / 消费者验真 /
遥感 / 产量预测 2 条）统一进 `AiNotAvailableController`：501 + 原因 + **可用替代**。
这样前端可以按契约定页面，用户看到的是后端原文而不是空白或假结果。
PRD 6.2 的推送注册 / 离线同步 / 定位上报**故意不占位** —— 它们的阻塞点是业务策略（推送通道、
离线范围、位置合规），占位会让人以为"接口有了"。

### 12.3 路径偏差（需产品确认）

PRD 6.3 写的是 `/api/v1/mobile/production/**`，本部署落在 `/api/v1/production/**`：
网关是按业务域分段路由的，为"客户端不同"再开一套前缀会让同一份业务出现两条入口；
且这两条规则 PC 端同样适用、可直接复用。若要严格对齐，网关加一条别名 location 即可，服务端不用动。

### 12.4 门禁与类型检查（顺带修掉两个真机隐患）

- `mobile` 组新增 **`tsc --noEmit`**：uni/vite 的 build 只转译不做类型检查，第一次真跑 tsc 就抓到：
  1. **微信小程序的 `wx.request` 不支持 PATCH** —— 而 `messages/read-all` 用的是 PATCH。
     已在后端同时开放 PUT（同一实现），移动端改用 PUT，PC 端继续 PATCH；
  2. `src/utils/request.ts` 用 uni-app 条件编译声明了两遍 `BASE_URL`，构建没事但 tsc 报重复声明
     —— 改成运行时判断（小程序没有 `window`）。
  另外补了 `src/env.d.ts`（.vue 类型声明 + uni 全局），否则 `main.ts` 一直报 TS2307。
- 实测：门禁 **通过 23 项 / 警告 4 / 跳过 1 / 失败 0**；写链路脚本 **75 条断言全绿**。

### 12.5 下一步（等这一步落地后）

7 个 V1.1 页面现在有了"真接口 + 真占位"两种基础：
`ai-alerts`、`ai-prescription`、`ai-remote-sensing`、`ai-yield-forecast`、`ai-assistant` 可以按
契约把页面接上（用户看到 501 原文 + 替代路径）；`harvest-block`（多地块休药期对比）已经
**有真数据支撑**（`plotIds=` 多地块查询），是这 7 个里最值得先做的一个。

## 14. 按建议执行「需要拍板」的三件事（2026-10-17 追加）

### 14.1 小程序开发者工具验收：**被 appid 挡住**（需要你提供）

已完成能自动化的部分：`manifest.json` 的 `mp-weixin.appid` 注释写明取值要求；产物经

**所以这一步必须用真实 appid**：你给一个小程序 appid（并在微信后台把网关 https 域名加进

### 14.3 测试稳定性：不再依赖滚轮选地块

联调脚本反复被 H5 滚轮 picker 拖垮（同一段位移在不同负载下走 4 项或 6 项、到底不循环、
慢速拖会被当成点击）。改为**深链预选**：给「投入品录入」与「新建任务」页也支持 `?plotId=`，
脚本直接用 URL 带地块进去，只在"土壤类型/灌溉方式"这类**末项目标**上用快甩。
顺带修了脚本里一个 SPA 陷阱：**hash 路由下同路径换查询串不会重新挂载**，
`onLoad(plotId)` 不会重跑 —— 门禁脚本现在会在同路径时强制 reload。

另外 `mobile-e2e` 的两个脚本**各自**会探活 H5 dev server，没起来就自己拉起（`scripts/lib/mobile-dev-server.mjs`），
门禁在每个脚本前也会再确保一次 —— 本机后台进程会被系统回收（这轮掉了多次），
环境没就绪不该算代码失败；真起不来则记 skip 并给出启动命令。
