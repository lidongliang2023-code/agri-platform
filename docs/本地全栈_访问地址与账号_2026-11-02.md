## 四、已知限制（不是账号问题）

1. **供应商端的"上架/接单"类写操作还差一步实名身份**：`supplier1` 能登录、能看到店铺与商品，
   但这类操作会走能力闸门 `s2b2c.supplier`，当前返回
   「需要已开通交易类业务身份（批发商 / 零售商 / 农户 / 合作社管理员）」。
   判定条件（`CapabilityFacadeImpl.isMallSupplier`）是「已加入经营主体」+ `platform_identity_application`
   里有 `approved` 且类型 ∈ `wholesaler/retailer/farmer/coop_admin`。
   **不需要手填实名记录**（`id_no_hash/salt` 有校验，直接插库会造出读不出来的脏身份）：
   `node scripts/provision-trade-access.mjs --accounts supplier1` 走的就是"提交身份申请 → 运营端审核通过"这条真实 HTTP 路径。
   演示时也可以继续用 `admin`（能绕过菜单限制）。
   纠正一处旧说法：**发货不走这个闸门** —— `/api/platform/order/ship` 只有 `s2b2c:fulfillment` 权限码
   与（2026-11-02 补上的）**供应商归属校验**，没有能力校验。
2. **生产管理 :80 直接打开会跳统一认证中心**：无登录态时是正常的 SSO 拦截，登录后回到目标页。
3. **移动端（8180-8184、8106/8109/8111/8114）是 uni-app H5**：建议用浏览器手机模拟宽度（375–414px）打开，PC 宽度下会显得留白很大。
4. 端口不能随手改：`ops/gateway/conf/conf.d/*.conf` 里每个 vhost 一个端口，改端口要同步改 Nginx 并 `-s reload`。

## 五、起停与排障

```bash
bash scripts/start-local-stack.sh            # 启动缺的组件（幂等）
bash scripts/start-local-stack.sh --status   # 只巡检
bash scripts/start-local-stack.sh --force    # 重启 10 个后端
```

- 后端日志：`__tmpout/logs/{core-platform,agri-s2b2c,...}.log`
- 网关日志：`C:\Users\71502\agri-gw\logs\{access,error}.log`
- 改了 `conf.d` 之后必须 `nginx -s reload`；只 reload 不 start（进程在跑 ≠ 配置生效）。
