## 二、怎么登录（实测流程，别踩空）

1. 打开任意端的地址，会跳到统一认证中心登录页（移动端是各自 uni-app 内的登录页）；
2. 登录页**默认是「手机号 + 验证码」**，切到「**账号密码登录**」；
3. 填入上表账号与对应密码，登录后自动回到刚才那个端；
4. **SSO 会话按端隔离**（浏览器里能看到 `agri_sso_session_<client>` 这组 cookie），
   所以换一个端会再跳一次登录页，用同一套账号再登一次即可 —— 这不是登录失败。

## 三、开发环境的短信验证码怎么取

短信通道没接真实服务商，`agri.auth.sms.mode=dev` 时验证码**只写后端日志 + Redis，不回传、不入库明文**，
所以页面上永远"收不到短信"。取码用：

```bash
node scripts/dev-sms-code.mjs                                  # 列出当前未过期的验证码
node scripts/dev-sms-code.mjs --phone 13800000001              # 发一次登录码并读出来
node scripts/dev-sms-code.mjs --phone 13800000001 --scene register
node scripts/dev-sms-code.mjs --phone 13800000001 --read-only   # 只读，不重发
```

规则：**5 分钟有效**、同一手机号 **60 秒内不能重发**、校验错 **5 次作废**。
只是登录的话，用「账号密码」标签更省事，不必走短信。

## 六、已知限制（不是账号问题）

1. **商城供应商能力（`s2b2c.supplier`）的判定只认 `mall_supplier` 这一种身份**：
   `CapabilityFacadeImpl.isMallSupplier` = 「已加入经营主体」+ `platform_identity_application` 里有
   `approved` 且类型 = `mall_supplier`。
   开通走真实两步，不手插实名记录（`id_no_hash/salt` 有校验，插库会造出读不出来的脏身份）：
   `POST /api/v1/sso/account/identity-applications` 提交 → `POST /api/v1/admin/identity-applications/{id}/review` 审核通过。
   **溯源相关的点检请优先用夹具账号 `lvyuanshop / Admin@123`**（角色 `S2B2C_SUPPLIER`、绑主体 2001 绿源农业合作社、
   入驻单已审核通过、名下有 3 个在册采收批次），由 `node scripts/provision-supplier-with-batches.mjs` 幂等维护。
   `supplier1` 曾被改绑到「五常大米专营有限公司」，该主体名下 0 个批次，
   `/api/supplier/production-batches` 于是**合法地**回空列表（跨主体不可见是设计）。
   发货不走这个闸门 —— `/api/platform/order/ship` 只有 `s2b2c:fulfillment` 权限码与供应商归属校验。
2. **交易供需发布按经营主体身份校验**：供应要求已审核的批发商、农户或合作社管理员身份；
   采购要求已审核的批发商或零售商身份。`admin` 在主体 2001 下只有合作社管理员身份，能发供应、不能发采购；
   测试采购请用 `13800138000`（漳州蕉塔，已审核批发商）。
3. **浏览器点检要按子系统取 SSO 会话**：`/authorize` 只认 `agri_sso_session_<clientId>`
   （如 `agri_sso_session_prod` / `agri_sso_session_mall-supplier`），`/sso/login-standalone` 只写全局 Cookie。
   注入全局 Cookie 去开子系统页面会被弹回登录页，症状与"前端坏了"一样。
4. **生产管理 :80 直接打开会跳统一认证中心**：无登录态时是正常的 SSO 拦截，登录后回到目标页。
5. **移动端（8180-8184、8106/8109/8111/8114）是 uni-app H5**：建议用浏览器手机模拟宽度（375–414px）打开。
6. 端口不能随手改：`ops/gateway/conf/conf.d/*.conf` 里每个 vhost 一个端口，改端口要同步改 Nginx 并 `-s reload`。
7. **换绑手机只在门户账号中心做**：发码走 `POST /api/v1/sso/account/phone/code`（要 SSO 会话），
   公开端点 `/api/v1/sso/sms/code` 已拒绝 `change_phone` 场景。
8. **门户的令牌刷新目前是断的**（2026-11-03 实测）：`/sso/login-standalone` 只写全局 `agri_refresh_token`，
   服务端按 `portal` 找 `agri_refresh_token_portal` 找不到 → 5003，表现是"访问令牌 2 小时后要重新登录"。尚未修。
